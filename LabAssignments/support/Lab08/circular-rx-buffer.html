    How to interpret the indices

    The write index identifies the next free location. The read index identifies the oldest unread byte. Neither index is the position within a command packet; packet parsing has its own state and payload count.

    Empty: read_index == write_index. Full: ((write_index + 1) & 0x0F) == read_index. One of the 16 locations remains unused, so the queue capacity is 15 bytes. Both indices wrap from 15 to 0 using (index + 1) & 0x0F.

    This demonstration models a software queue, not the PIC16F883's two-character EUSART hardware FIFO. Firmware must still service the hardware receiver often enough to avoid overrun. A full software queue rejects the next byte in this example; real firmware must also choose a recovery policy.
